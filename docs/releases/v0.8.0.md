# v0.8.0 Release Notes

## Overview

`v0.8.0` is the existing Git-tagged platform milestone. This document describes
that historical release without moving or rewriting the tag.

## Highlights

- Security Platform foundation for internal security operations.
- Contractor Requests module with lifecycle, assignments and collaboration.
- Contractor Portal for tenant-scoped contractor work.
- Internal dashboard and administration workspace.
- Local authentication, RBAC, cookie sessions and CSRF protection.

## Architecture

- Frontend: React, TypeScript, Vite, React Router and shared UI primitives.
- Backend: FastAPI, SQLAlchemy, Alembic and Pydantic.
- Database: SQLite for local development; PostgreSQL remains the production
  target, not the active local database.
- Operations: PowerShell start/stop scripts and demo seed support.

## Security

- Cookie-based local authentication.
- CSRF validation on state-changing routes.
- RBAC and tenant isolation for contractor data.
- Password policy and temporary-password lifecycle.
- Audit/history foundation for administrative and request activity.

## Compatibility

The tagged release preserves Contractor Requests API behavior, approved request
statuses, assignment workflow, RequestHistory semantics and contractor tenant
isolation as implemented at the tag.

## Validation

Historical validation was performed before the tag was created. Current
post-tag validation is tracked separately in
[NEXT_RELEASE.md](NEXT_RELEASE.md) and [PHASE_E_ACCEPTANCE.md](PHASE_E_ACCEPTANCE.md).

## Known Limitations

- Production deployment hardening was not complete.
- PostgreSQL/Redis production infrastructure was not finalized.
- Notification Center and Scheduler were not implemented as platform services.
- External LDAP/ADFS production validation was not complete.

## Upgrade Notes

Use normal repository migration and seed commands for local development:

```powershell
cd backend
uv run alembic upgrade head
uv run python -m app.scripts.seed_demo
```

## Rollback Notes

Rollback from later development states should restore the database backup made
before migration and check out the existing `v0.8.0` tag. Do not recreate or
move the tag.

## Next Milestone

The recommended next milestone is `v0.9.0`, focused on Notification Center and
Scheduler after release-readiness work is reviewed.
